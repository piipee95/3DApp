# KultiApp V3.5: seguridad y calidad automáticas

Revisiones automáticas en GitHub; todas son gratis porque el repositorio es público:

- **Tests** (`.github/workflows/test.yml`): ahora corre `npm run lint` (ESLint) antes de `npm test`. Detecta errores típicos: variables mal escritas, código que nunca se ejecuta, claves repetidas, etc. Esto también aplica a los cambios hechos con ChatGPT u otras herramientas.
- **CodeQL** (`.github/workflows/codeql.yml`): análisis de seguridad del JavaScript en cada PR, en cada cambio a `main` y una vez por semana. Los hallazgos aparecen en GitHub, en Security → Code scanning.
- **Secrets** (`.github/workflows/secrets.yml`): gitleaks bloquea commits que contengan contraseñas, llaves privadas o tokens. La llave publicable de Supabase (`sb_publishable_…`) es pública por diseño y está permitida en `.gitleaks.toml`. `.gitleaksignore` solo excluye una contraseña falsa usada en una prueba.
- **Dependabot** (`.github/dependabot.yml`): cada semana propone, con un PR, actualizar los paquetes de npm y las acciones de GitHub. Los arreglos de seguridad llegan apenas existen.

## Para quien edite el repo (persona, ChatGPT o Claude)
1. Trabajar siempre sobre el `main` más reciente.
2. Antes de subir cambios, correr `npm run lint` y `npm test`.
3. Nunca subir claves secretas: la `service_role` de Supabase, contraseñas, tokens de Vercel o de GitHub.
4. Los PR de Dependabot se aceptan si los tests pasan en verde.

## Activar en GitHub (una vez, lo hace el dueño del repo)
En Settings → Code security, activar «Dependabot alerts», «Dependabot security updates» y «Secret scanning / Push protection».
