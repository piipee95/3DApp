# KultiApp V1.3 — Cotización y producción

## Flujos

1. En **Recursos**, registrar filamentos (nombre, marca/material, color,
   precio/kg) e impresoras (nombre y potencia eléctrica kW). Se pueden editar
   y desactivar; no se eliminan registros usados como referencia.
2. En un producto, elegir un filamento del catálogo en cada color y un perfil
   de impresora. Los valores se copian a la impresión. Cambiar el catálogo no
   cambia productos anteriores. Para aplicar un precio nuevo, volver a elegir
   el material y guardar. La energía se recalcula al seleccionar la máquina o
   pulsar **Calcular filamento + electricidad** después de cambiar el tiempo.
3. En **Producto**, indicar opcionalmente un precio final por unidad. Incluye
   IVA cuando está habilitado. Vacío conserva el precio automático; cero es
   un precio explícito. Se muestra margen y utilidad del precio final, con aviso
   si genera pérdida. Los escenarios comerciales siguen usando el margen objetivo.
4. En **Resumen → Crear pedido de producción**, guardar el producto y confirmar
   cliente/referencia, cantidad, precio y entrega. Al variar cantidad, revisar la
   estimación proporcional: varias piezas en una cama pueden compartir tiempo.
5. En **Producción**, abrir un pedido y registrar estado, entrega, costo real
   base, costo adicional por fallas, gramos reales, horas y notas. Un valor vacío
   es pendiente; cero significa registrado. El costo real base debe incluir los
   costos del lote excepto las fallas registradas aparte.

Estados: Pendiente → Imprimiendo → Armado → Listo → Entregado; también Cancelado.
Se permite cambiar de estado manualmente para corregir o retomar un trabajo.
Los atrasos se calculan con la fecha local del navegador. No se envían recordatorios.

## Historial y métricas

Los pedidos conservan título, unidades, precio, IVA y estimación del lote.
Cambiar o eliminar el producto no modifica estos valores. La cotización del
pedido comparte su precio registrado y no incluye costos internos ni utilidad.
Eliminar un producto deja el pedido disponible con su referencia desacoplada.

- Venta bruta = unidades × precio final por unidad.
- Venta neta = venta bruta / (1 + IVA), si aplica.
- Costo real = costo real base + fallas adicionales.
- Utilidad real = venta neta − costo real.
- Desviación de costo = costo real − costo estimado.

Gramos y horas reales son registros informativos; no recalculan automáticamente
el costo real porque un pedido puede usar materiales y condiciones diferentes.
La utilidad aquí es de fabricación; no incluye conceptos que no se hayan cargado
al costo. No es un módulo contable, de facturación ni de pagos.

Productos: búsqueda, orden por nombre/costo/precio/margen/modificación y filtros
de rentabilidad. Los productos sin costos registrados se identifican por separado.

## Datos y permisos

Migración aplicada: `kultiapp_v13_catalogs_pricing_production`.
Referencia del esquema: [SCHEMA_V13.sql](SCHEMA_V13.sql).
Nuevas tablas: `workspace_resources`, `production_orders`, ambas con RLS.
Miembros pueden leer. Propietarios y editores pueden crear/actualizar dentro del
workspace. No hay acceso anónimo ni eliminación de pedidos/recursos desde el cliente.
Se validó además que un pedido no pueda referenciar un producto de otro workspace.

La RPC SECURITY INVOKER `save_product_bundle_v3` conserva el guardado atómico V2
y agrega precio final y perfiles de impresora. V1/V2 siguen disponibles.
El asesor no detectó problemas nuevos de RLS. Permanece el aviso previo sobre
[protección contra contraseñas filtradas](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

## Validación

```sh
NODE_PATH=/tmp/kulti-test/node_modules node tests/v12.test.cjs
NODE_PATH=/tmp/kulti-test/node_modules node tests/v13.test.cjs
node --check app.js
git diff --check
```

Dependencia de pruebas: jsdom@26.1.0; instalación documentada en V1_2.md.
Se probaron catálogos, precio manual, cálculo eléctrico, snapshots, guardado de
pedidos y costos reales, filtros, borradores, cotizaciones y permisos de lectura.
La prueba autenticada de base de datos verificó aislamiento entre workspaces,
restricciones de viewer/anon y estabilidad de pedidos al cambiar el producto;
todos los datos de prueba se revirtieron con ROLLBACK.
Se revisaron en Chromium las vistas y diálogos de producción/recursos entre
320 y 1440 px, además de PNG/PDF, fotos y recuperación de borradores.
